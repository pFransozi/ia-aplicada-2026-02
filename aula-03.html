Primeira análise

O problema parece simples. A representação ainda não existe.

Dizer “leve o robô ao laboratório” descreve uma intenção humana. Para programar uma solução, precisamos decidir quais elementos dessa situação serão transformados em estruturas manipuláveis pelo computador.

Por enquanto, não procure o caminho. A pergunta da aula é anterior: como representar o problema de maneira suficiente para que uma busca possa acontecer depois?

Abstração

O mundo real contém informação demais

Uma representação computacional seleciona características relevantes e ignora outras. Abstrair não é “simplificar por preguiça”: é decidir quais detalhes são necessários para o objetivo do problema.

Formulação

A anatomia de um problema de busca

Agora tornamos a descrição precisa. Cada elemento responde a uma pergunta diferente e ajuda a construir a representação que será utilizada pelos algoritmos nas próximas aulas.

01

Entrada

Pergunta: que informações o sistema recebe?

No exemplo: mapa, posição inicial e destino.

02

Estado

Pergunta: o que descreve uma situação relevante?

No modelo inicial: a posição atual do robô.

03

Estado inicial

Pergunta: onde o problema começa?

No exemplo: Recepção.

04

Ações

Pergunta: o que pode ser feito em cada estado?

No exemplo: mover para um local diretamente conectado.

05

Modelo de transição

Pergunta: dado um estado e uma ação, qual novo estado resulta?

O robô passa do local atual para o destino escolhido.

06

Restrições

Pergunta: o que não é permitido?

Não atravessar paredes nem mover para locais desconectados.

07

Objetivo

Pergunta: qual situação queremos alcançar?

No exemplo: estar no Laboratório.

08

Saída

Pergunta: o que o sistema deve produzir?

Uma sequência válida de movimentos.

09

Avaliação / custo

Pergunta: como comparamos soluções?

Quantidade de movimentos, distância, tempo ou outro custo associado ao caminho.

Uma distinção importante

Objetivo, sucesso e avaliação não são a mesma coisa

Objetivo

Descreve a situação desejada.

Ex.: chegar ao Laboratório.

Critério de sucesso

Permite verificar se a solução é válida.

Ex.: o robô chegou ao destino sem violar restrições.

Critério de avaliação

Permite comparar soluções válidas.

Ex.: qual caminho utiliza menos movimentos?
Contexto de IA simbólica: ao representar explicitamente estados, ações e objetivos, estamos entrando em uma tradição clássica da Inteligência Artificial. O foco desta aula é a formulação; os mecanismos de busca aparecem na próxima etapa.

Primeiro código

Da representação conceitual para Python

Não vamos implementar BFS ou DFS ainda. Primeiro, vamos programar o problema sobre o qual esses algoritmos trabalharão.

Python01 · estado e objetivo
estado_inicial = "recepcao"
objetivo = "laboratorio"

print(estado_inicial)
print(objetivo)

O que estamos representando?

As strings não são as salas reais. Elas são símbolos usados pelo programa para representar elementos do domínio.

  • "recepcao" representa o estado inicial.
  • "laboratorio" representa o objetivo.
Python02 · ações e transições
mapa = {
    "recepcao": ["corredor"],
    "corredor": [
        "recepcao",
        "sala_101",
        "copa",
        "laboratorio"
    ],
    "sala_101": ["corredor"],
    "copa": ["corredor"],
    "laboratorio": ["corredor"]
}

def acoes_possiveis(estado):
    return mapa[estado]

O dicionário representa as conexões relevantes do ambiente

Para cada estado, registramos quais outros estados podem ser alcançados por uma ação válida. O dicionário é uma representação do domínio, não o ambiente real.

  • As chaves são estados.
  • As listas representam possibilidades de transição.
  • A função responde “o que posso fazer daqui?”.
Python03 · teste de objetivo
def objetivo_atingido(estado):
    return estado == objetivo

print(objetivo_atingido("corredor"))
# False

print(objetivo_atingido("laboratorio"))
# True

O programa já reconhece sucesso

Ele ainda não sabe encontrar sozinho um caminho. Mas já sabe identificar estados, listar ações válidas e verificar quando o objetivo foi alcançado.

Três ideias diferentes

Estado: uma situação possível.

Espaço de estados: conjunto de situações alcançáveis pelas ações disponíveis.

Solução: uma sequência válida de ações que leva do estado inicial a um estado objetivo.

Importante: nesta aula estamos construindo o espaço. Ainda não decidimos em que ordem os estados serão explorados. Essa decisão é exatamente o que diferencia estratégias de busca como BFS e DFS.

Qualidade da representação

Uma representação pode ser simples e ainda assim estar errada

Vamos alterar o problema: agora o robô precisa buscar um pacote na Sala 101 antes de entregá-lo no Laboratório.

Representação insuficiente

estado = "corredor"

Ela não distingue duas situações importantes: estar no corredor com o pacote ou sem o pacote.

estado = "corredor"
→

Representação ampliada

Agora o estado contém duas informações relevantes.

estado = {
    "local": "corredor",
    "possui_pacote": False
}
Regra de projeto: o computador só consegue distinguir aquilo que decidimos representar. Uma informação omitida pode tornar impossível encontrar ou validar a solução correta.
