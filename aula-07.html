Aula 07 · Raciocínio sob incerteza

Do sistema especialista ao diagnóstico probabilístico

Vamos transformar conhecimento probabilístico em um programa capaz de receber evidências, calcular hipóteses e indicar qual delas é mais provável.

Começar pela Aula 06 Ver o sistema em Python
Pergunta orientadora
Como um sistema baseado em conhecimento pode escolher entre várias hipóteses quando as evidências não são conclusivas?

Visão da aula

O percurso desta aula

O objetivo não é apenas calcular Bayes. O objetivo é compreender como a incerteza modifica a arquitetura de um sistema baseado em conhecimento.

1RetomarRelembrar como fatos e regras produzem conclusões em um sistema especialista.
2RepresentarSubstituir conclusões rígidas por hipóteses associadas a probabilidades.
3InferirUsar evidências para atualizar a probabilidade de cada hipótese.
4ImplementarConstruir em Python um pequeno motor de inferência probabilística.
Ao final: o estudante deverá conseguir explicar a diferença entre um sistema baseado apenas em regras e um sistema baseado em conhecimento com inferência probabilística, além de implementar uma versão simplificada desse mecanismo.

Retomada da Aula 06

O que muda quando uma regra não é suficiente?

Na Aula 06, representamos conhecimento por meio de fatos e regras. Um sistema simples poderia conter:

# Verifica se as duas condições da regra são verdadeiras.
if timeout and pool_esgotado:
    # Em um sistema determinístico, a regra produz diretamente a conclusão.
    conclusao = "falha_banco"

O código acima funciona quando aceitamos a regra como determinística: se as duas condições forem verdadeiras, a conclusão é produzida.

Entretanto, em um diagnóstico real, um timeout pode ser provocado por diferentes causas. O banco pode estar indisponível, a rede pode estar degradada ou a aplicação pode estar sobrecarregada. Nesse caso, a evidência não determina sozinha uma única conclusão.

Sistema baseado apenas em regrasSistema com inferência probabilística
SE condição ENTÃO conclusãoCompara várias hipóteses possíveis.
A regra produz uma conclusão quando suas condições são satisfeitas.Cada evidência aumenta ou reduz a plausibilidade das hipóteses.
O resultado tende a ser tratado como verdadeiro ou falso dentro do modelo.O resultado é uma distribuição de probabilidades.
Exemplo: “timeout e pool esgotado implicam falha no banco”.Exemplo: “dadas essas evidências, falha no banco é a hipótese mais provável”.

Continuidade entre as aulas: não abandonamos a ideia de sistema especialista. Continuamos representando conhecimento do domínio, mas agora o mecanismo de inferência precisa lidar explicitamente com incerteza.

Sistema probabilístico

Como isso se transforma em um programa?

Uma implementação simplificada pode ser organizada em quatro partes.

1 · Base de conhecimentoArmazena hipóteses, probabilidades iniciais e relações entre hipóteses e evidências.
2 · Evidências observadasRecebe os fatos disponíveis para o caso atual, como timeout ou pool esgotado.
3 · Motor de inferênciaCombina o conhecimento armazenado com as evidências por meio de Bayes.
4 · ResultadoRetorna a probabilidade posterior de cada hipótese e pode indicar a hipótese mais provável.

O conhecimento agora contém números

Considere três causas possíveis para um timeout:

HipótesePriorP(timeout | hipótese)
Falha no banco0,100,80
Falha de rede0,300,60
Sobrecarga da aplicação0,600,40

Esses valores podem ser definidos a partir de dados históricos ou de conhecimento especializado. O programa não aprende necessariamente esses valores durante sua execução. Quando eles são fornecidos previamente, estamos construindo um sistema baseado em conhecimento com inferência probabilística.

# A base de conhecimento reúne as hipóteses consideradas pelo sistema.
base_conhecimento = {
    "falha_banco": {
        # Probabilidade inicial da hipótese antes de observar novas evidências.
        "prior": 0.10,

        # P(timeout | falha_banco)
        "evidencias": {
            "timeout": 0.80
        }
    },
    "falha_rede": {
        "prior": 0.30,

        # P(timeout | falha_rede)
        "evidencias": {
            "timeout": 0.60
        }
    },
    "sobrecarga_aplicacao": {
        "prior": 0.60,

        # P(timeout | sobrecarga_aplicacao)
        "evidencias": {
            "timeout": 0.40
        }
    }
}
Distinção importante: a base de conhecimento contém o que o sistema sabe sobre o domínio. O motor de inferência usa esse conhecimento para analisar um caso específico.

Fundamento probabilístico

O que é o Teorema de Bayes?

O Teorema de Bayes permite atualizar a probabilidade de uma hipótese depois que uma nova evidência é observada.

No contexto desta aula, queremos responder perguntas de diagnóstico. Por exemplo: depois de observar um timeout, qual é a probabilidade de existir uma falha no banco?

P(H|E) = [P(E|H) × P(H)] / P(E)

A fórmula relaciona quatro elementos. Antes de calcular, é importante saber exatamente o que cada símbolo representa.

H · Hipótese

É a explicação que queremos avaliar.

Exemplo: H = “há falha no banco”.

E · Evidência

É a informação observada no caso atual.

Exemplo: E = “ocorreu timeout”.

P(H) · Prior

É a probabilidade da hipótese antes de observar a nova evidência.

Exemplo: P(H)=0,10 significa que, antes do timeout, atribuímos 10% de probabilidade à falha no banco.

P(E|H) · Verossimilhança

É a probabilidade de observar a evidência se a hipótese for verdadeira.

Exemplo: P(timeout|falha_banco)=0,80.

P(E) · Probabilidade da evidência

É a probabilidade total de observar a evidência, considerando todas as formas pelas quais ela pode ocorrer.

Exemplo: a chance total de ocorrer timeout, seja por falha no banco ou por outras causas.

P(H|E) · Posterior

É a probabilidade da hipótese depois de observar a evidência.

Exemplo: a probabilidade de falha no banco depois que o timeout foi observado.

O símbolo | significa “dado que”

P(E|H)

Probabilidade da evidência, dado que a hipótese é verdadeira.

P(timeout | falha_banco)

P(H|E)

Probabilidade da hipótese, dado que a evidência foi observada.

P(falha_banco | timeout)

A ordem importa: P(timeout|falha_banco) e P(falha_banco|timeout) respondem a perguntas diferentes. O Teorema de Bayes permite passar do primeiro tipo de informação para o segundo.

Leitura da atualização: começamos com uma crença inicial sobre a hipótese, P(H), observamos uma evidência e calculamos uma nova crença, P(H|E). É essa atualização que o motor de inferência implementa.

Exemplo resolvido 1

Uma hipótese e uma evidência

Exemplo respondido

Hipótese H: há falha no banco.
Evidência E: ocorreu timeout.

  • P(H)=0,10
  • P(E|H)=0,80
  • P(E|¬H)=0,20

Passo 1 · Começar pelo prior

Antes do timeout, a probabilidade atribuída à falha no banco é de 10%.

Passo 2 · Verificar quanto a evidência favorece cada cenário

O timeout aparece em 80% dos casos com falha no banco, mas também aparece em 20% dos casos sem falha no banco.

Passo 3 · Atualizar a hipótese

P(H|E) = (0,80 × 0,10) / [(0,80 × 0,10) + (0,20 × 0,90)]
P(H|E) = 0,08 / 0,26 ≈ 0,308

Após observar o timeout, a probabilidade da hipótese sobe de 10% para aproximadamente 30,8%.

Interpretação: o timeout favorece a hipótese de falha no banco, mas não é suficiente para torná-la a única explicação possível.

Exemplo resolvido 2

Várias hipóteses competindo pela mesma evidência

Agora o sistema precisa comparar diferentes explicações para o mesmo fato observado.

Exemplo respondido

Foi observado um timeout. O sistema considera três causas possíveis:

  • H₁: falha no banco;
  • H₂: falha de rede;
  • H₃: sobrecarga da aplicação.

Para simplificar o exemplo, vamos assumir que essas três hipóteses são mutuamente exclusivas e representam todas as causas consideradas pelo modelo. Assim, o sistema precisa distribuir sua crença entre essas três possibilidades.

Passo 1 · Conhecimento inicial sobre as hipóteses

Antes de observar o timeout, o sistema já possui uma probabilidade inicial para cada hipótese. Esse valor é o prior.

HipótesePriorInterpretação
Falha no banco0,10Antes da evidência, 10% dos casos são atribuídos a falha no banco.
Falha de rede0,30Antes da evidência, 30% dos casos são atribuídos a falha de rede.
Sobrecarga da aplicação0,60Antes da evidência, 60% dos casos são atribuídos a sobrecarga.

Os priors somam 1:

0,10 + 0,30 + 0,60 = 1,00

Passo 2 · Quão esperado é o timeout em cada hipótese?

Agora usamos a probabilidade da evidência condicionada a cada hipótese. Em outras palavras: se esta hipótese for verdadeira, com que frequência esperamos observar timeout?

HipóteseP(timeout | H)Leitura
Falha no banco0,80Se houver falha no banco, há 80% de chance de ocorrer timeout.
Falha de rede0,60Se houver falha de rede, há 60% de chance de ocorrer timeout.
Sobrecarga da aplicação0,40Se houver sobrecarga, há 40% de chance de ocorrer timeout.

Passo 3 · Combinar o prior com a evidência

Para cada hipótese, multiplicamos o prior por P(timeout|H). O resultado indica quanto aquela hipótese contribui para os casos em que observamos timeout.

Falha no banco
0,10 × 0,80 = 0,080

Embora timeout seja muito comum quando o banco falha, essa hipótese tinha um prior baixo.

Falha de rede
0,30 × 0,60 = 0,180

A hipótese começa com um prior maior e o timeout também é relativamente provável nesse cenário.

Sobrecarga da aplicação
0,60 × 0,40 = 0,240

O timeout é menos característico dessa hipótese, mas ela começa com o maior prior.

Passo 4 · Calcular a probabilidade total do timeout

Os valores 0,080, 0,180 e 0,240 representam as três formas previstas pelo modelo de observar um timeout.

Por isso, somamos:

P(timeout) = 0,080 + 0,180 + 0,240 = 0,50

O valor 0,50 não é arbitrário. Ele representa a probabilidade total da evidência dentro deste modelo.

Passo 5 · Normalizar e obter os posteriores

Até aqui, os valores não representam uma distribuição final sobre as hipóteses. Para obter as probabilidades depois de observar o timeout, dividimos cada valor por P(timeout)=0,50.

HipóteseCálculoPosterior
Falha no banco0,080 / 0,5016%
Falha de rede0,180 / 0,5036%
Sobrecarga da aplicação0,240 / 0,5048%

Agora os posteriores somam 100%:

16% + 36% + 48% = 100%

Passo 6 · Interpretar a predição

Depois de observar o timeout, o sistema passa a atribuir:

  • 16% para falha no banco;
  • 36% para falha de rede;
  • 48% para sobrecarga da aplicação.

Como 48% é o maior posterior, a predição do sistema é sobrecarga da aplicação.

Importante: 48% não significa certeza. Significa apenas que, entre as hipóteses representadas e considerando a evidência observada, sobrecarga da aplicação recebeu o maior suporte probabilístico.

O que Bayes fez aqui: combinou a frequência inicial de cada hipótese com o quanto a evidência é esperada em cada uma delas. Depois, os valores foram normalizados para formar uma nova distribuição de probabilidades.

Implementação

Um pequeno motor de inferência probabilística em Python

Vamos transformar exatamente o exemplo anterior em código.

# Base de conhecimento probabilística.
# Cada hipótese possui um prior e P(timeout | hipótese).
base_conhecimento = {
    "falha_banco": {
        "prior": 0.10,
        "evidencias": {"timeout": 0.80}
    },
    "falha_rede": {
        "prior": 0.30,
        "evidencias": {"timeout": 0.60}
    },
    "sobrecarga_aplicacao": {
        "prior": 0.60,
        "evidencias": {"timeout": 0.40}
    }
}


def inferir(base, evidencia):
    # Guarda um valor proporcional ao posterior de cada hipótese.
    scores = {}

    # Analisa todas as hipóteses disponíveis na base.
    for hipotese, dados in base.items():
        # P(H): probabilidade da hipótese antes da evidência.
        prior = dados["prior"]

        # P(E|H): probabilidade da evidência se a hipótese for verdadeira.
        p_e_dado_h = dados["evidencias"][evidencia]

        # Calcula P(H) × P(E|H).
        # Ainda não é o posterior final, pois falta normalizar.
        scores[hipotese] = prior * p_e_dado_h

    # Soma os scores. Neste exemplo, o total corresponde a P(E).
    total = sum(scores.values())

    # Normaliza os scores para que as probabilidades somem 1.
    posteriores = {
        hipotese: score / total
        for hipotese, score in scores.items()
    }

    # Escolhe a hipótese com maior probabilidade posterior.
    predicao = max(posteriores, key=posteriores.get)

    return posteriores, predicao


# Evidência observada no caso atual: ocorreu timeout.
posteriores, predicao = inferir(
    base_conhecimento,
    "timeout"
)

# Exibe a probabilidade posterior de cada hipótese.
for hipotese, probabilidade in posteriores.items():
    print(f"{hipotese}: {probabilidade:.1%}")

# Exibe a hipótese mais provável segundo o modelo.
print("Predição:", predicao)
falha_banco: 16.0% falha_rede: 36.0% sobrecarga_aplicacao: 48.0% Predição: sobrecarga_aplicacao

O que cada parte do código representa?

No programaNo sistema especialista
base_conhecimentoConhecimento probabilístico sobre o domínio.
"timeout"Evidência observada no caso atual.
inferir()Motor de inferência.
posterioresGrau de crença atualizado em cada hipótese.

Observe: o código não contém uma regra do tipo if timeout: falha_banco. Ele mantém várias explicações possíveis, calcula a força de cada uma e somente depois identifica a hipótese mais provável.

Exemplo resolvido 3

Uma segunda evidência pode alterar a predição

Exemplo respondido

Além do timeout, observamos que o pool de conexões está esgotado. Acrescentamos esse conhecimento à base:

HipóteseP(timeout | H)P(pool esgotado | H)
Falha no banco0,800,90
Falha de rede0,600,05
Sobrecarga da aplicação0,400,25

Para este exemplo didático, assumiremos que as duas evidências são condicionalmente independentes dada cada hipótese. Assim, podemos calcular:

score(H) = P(H) × P(timeout|H) × P(pool_esgotado|H)
HipóteseScorePosterior normalizado
Falha no banco0,10 × 0,80 × 0,90 = 0,07251,1%
Falha de rede0,30 × 0,60 × 0,05 = 0,0096,4%
Sobrecarga da aplicação0,60 × 0,40 × 0,25 = 0,06042,6%

Com apenas o timeout, a predição era sobrecarga da aplicação. Depois de incorporar o pool esgotado, a hipótese mais provável passa a ser falha no banco, com aproximadamente 51,1%.

Agora o código recebe várias evidências

# A base agora descreve duas evidências para cada hipótese.
base_conhecimento = {
    "falha_banco": {
        "prior": 0.10,
        "evidencias": {
            # P(timeout | falha_banco)
            "timeout": 0.80,

            # P(pool_esgotado | falha_banco)
            "pool_esgotado": 0.90
        }
    },
    "falha_rede": {
        "prior": 0.30,
        "evidencias": {
            "timeout": 0.60,
            "pool_esgotado": 0.05
        }
    },
    "sobrecarga_aplicacao": {
        "prior": 0.60,
        "evidencias": {
            "timeout": 0.40,
            "pool_esgotado": 0.25
        }
    }
}


def inferir(base, evidencias_observadas):
    # Guarda um score para cada hipótese.
    scores = {}

    for hipotese, dados in base.items():
        # Começamos pela probabilidade inicial P(H).
        score = dados["prior"]

        # Multiplicamos pelas probabilidades das evidências observadas.
        # Aqui assumimos independência condicional entre elas dada a hipótese.
        for evidencia in evidencias_observadas:
            score *= dados["evidencias"][evidencia]

        scores[hipotese] = score

    # Soma os scores para normalizar os resultados.
    total = sum(scores.values())

    # Converte os scores em probabilidades posteriores que somam 1.
    posteriores = {
        hipotese: score / total
        for hipotese, score in scores.items()
    }

    # Retorna como predição a hipótese com maior posterior.
    predicao = max(posteriores, key=posteriores.get)

    return posteriores, predicao


# O caso atual apresenta duas evidências.
posteriores, predicao = inferir(
    base_conhecimento,
    ["timeout", "pool_esgotado"]
)

# Mostra a distribuição posterior completa.
for hipotese, probabilidade in posteriores.items():
    print(f"{hipotese}: {probabilidade:.1%}")

# Mostra a hipótese selecionada pelo sistema.
print("Predição:", predicao)
falha_banco: 51.1% falha_rede: 6.4% sobrecarga_aplicacao: 42.6% Predição: falha_banco
Hipótese do modelo: a multiplicação das evidências pressupõe independência condicional dada a hipótese. Se as evidências forem fortemente dependentes mesmo depois de fixarmos a hipótese, esse modelo simplificado não é adequado.

Base de conhecimento

De onde vêm as probabilidades?

Conhecimento especializado

Especialistas do domínio podem estimar frequências e relações plausíveis entre hipóteses e evidências.

Dados históricos

Registros anteriores podem ser usados para estimar priors e probabilidades condicionais.

Se as probabilidades são definidas previamente e o programa apenas aplica o mecanismo de inferência, temos um sistema baseado em conhecimento probabilístico. Se um algoritmo aprende esses parâmetros a partir de exemplos, entramos também no domínio de aprendizado de máquina.

Não confundir: um fator de certeza associado a uma regra e uma probabilidade bayesiana não são a mesma coisa. Existem diferentes formalismos para representar incerteza em sistemas especialistas.

Leitura crítica

O que a predição significa?

Maior probabilidade não significa certeza

Selecionar a maior posterior é uma política de decisão. O sistema deve preservar as demais probabilidades para representar a incerteza.

O resultado depende da base de conhecimento

Priors ou probabilidades condicionais inadequadas produzem inferências inadequadas.

As hipóteses precisam representar o problema

Se uma causa importante não foi incluída, a normalização redistribuirá a probabilidade apenas entre as hipóteses disponíveis.

Dependências precisam ser modeladas

Multiplicar evidências sem verificar independência condicional pode produzir excesso de confiança.
